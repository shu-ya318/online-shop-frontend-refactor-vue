# docs/setup 撰寫規範

只適用於 `docs/setup/` 內「說明單一設定檔或入口檔」的文件。範本以 [index-html.md](setup/index-html.md)、[main-ts.md](setup/main-ts.md) 為準。`setup/index.md` 是總覽筆記,不套用本規範。

## 結構

```markdown
# 檔名(所在資料夾)

1~2 句總覽:這個檔案是什麼,依由上到下分成哪幾個區域。

## 區域名稱(依檔案由上到下的順序)

### 設定語法對應效果

| 設定   | 效果     |
| ------ | -------- |
| `語法` | 一行說明 |

### 應避免的錯誤

- 錯誤N：現象(一句話)
  - 補充原因(一句話)
- 後果
  - 使用者或開發者實際看到的現象
- Vue 版做法
  - 具體怎麼寫
```

## 規則

- H1 用檔名;若檔案不在根目錄,後面加括號寫資料夾,例如 `main.ts(src/)`。
- 一個 H2 對應檔案中的一個區域,順序與檔案內容一致。
- 每個 H2 固定有兩個 H3,名稱不改:`設定語法對應效果`、`應避免的錯誤`。
- 錯誤編號 `錯誤N` 在整份文件內連續,不隨 H2 重新計算。
- 每個錯誤都要有「現象 → 後果 → Vue 版做法」三層,缺一不可。
- 「後果」寫實際會看到的現象(畫面、錯誤訊息、指令失敗),不寫「可能造成問題」這類空話。
- 新增或改動來自原 React 版的差異時,在「Vue 版做法」寫清楚對應關係。

## 敘述風格

- 目標:直接口述給新手工程師聽。
- 一句一個重點,句子盡量不超過兩行;不寫長段落。
- 表格「效果」欄一行寫完。
- 專有名詞第一次出現時用括號補一句白話解釋。
- 程式碼、檔名、指令一律用反引號。

## 內容真實性

- 只寫在程式碼或設定檔中確認過的事實;寫之前先讀對應原始檔。
- 不確定的內容寫「待確認」並詢問作者,不要自行補全。
- 不寫已過時的步驟編號(例如「第 11 步」),除非 `setup/index.md` 的總表仍有該步驟。

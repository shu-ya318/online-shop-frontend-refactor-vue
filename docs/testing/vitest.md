# vitest.config.ts

分為「執行環境」、「時區」、「setupFiles」、「測試檔位置」四個區域。

## 執行環境

### 設定語法對應效果

| 設定                                       | 效果                                    |
| ------------------------------------------ | --------------------------------------- |
| 預設環境 `jsdom`                           | 元件測試有 DOM,並可掛載 Vuetify         |
| 測試檔第一行 `// @vitest-environment node` | services、utils 測試改用 Node 環境,較快 |

### 應避免的錯誤

- services、utils 這類不需要 DOM 的測試仍使用 jsdom,執行較慢。

## 時區

### 設定語法對應效果

| 設定                          | 效果                                      |
| ----------------------------- | ----------------------------------------- |
| `test.env.TZ = 'Asia/Taipei'` | 固定時區,日期相關測試在任何機器上結果一致 |

### 應避免的錯誤

- 不固定時區,日期相關測試的結果會因機器而異。

## setupFiles

### 設定語法對應效果

| 設定                     | 效果                                                             |
| ------------------------ | ---------------------------------------------------------------- |
| 指向 `src/test/setup.ts` | 補上 jsdom 沒有的 `ResizeObserver` 與 `matchMedia`(Vuetify 需要) |

### 應避免的錯誤

- 沒補這兩個 API:Vuetify 元件測試會出錯(這是元件測試常見的坑)。

## 測試檔位置

### 設定語法對應效果

| 設定                                                                           | 效果                                     |
| ------------------------------------------------------------------------------ | ---------------------------------------- |
| 單元測試放在被測層級的 `__tests__/`(如 `services/__tests__/`),檔名 `*.spec.ts` | 測試與被測層級相鄰,好找也不撞名          |
| 共用工具 `setup.ts`、`testUtils.ts` 放 `src/test/`                             | 工具不被當成測試檔,也不混在 `__tests__/` |
| `e2e/**` 被排除                                                                | e2e 交給 Playwright                      |

### 應避免的錯誤

- 測試路徑與第 8 步調整後的專案結構不一致。
